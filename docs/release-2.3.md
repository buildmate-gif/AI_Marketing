# AIマーケティングスイート 2.3 製品仕様と検証記録

2026年11月19日。対象は、日本の中小企業を担当し、改善案を選んで顧客に説明し、翌月の結果まで追う支援担当者。既存の8業種対応を維持し、工務店を最初の一貫した利用例に選んだ。対象業務は、工務店なら来場・見積相談、通販なら購入、BtoBなら資料請求から商談への改善である。

## 利用者ができること

| 利用場面 | 入力と動き | 受け取るもの |
|---|---|---|
| 初回相談 | improve に対象URLと任意の目標を渡す。公開ページを調査し、観察内容から影響・根拠・着手のしやすさを判断する | 顧客用HTML、担当者用の監査書、次回比較用の履歴 |
| 改善を決める | 最大3件の施策について対象URL・確認日・観察・仮説・修正内容・確認指標を読む | 顧客に修正理由を説明できる施策リスト。確認できた施策だけを載せる |
| 翌月に振り返る | 同じURL・同じ案件フォルダで再診断し、施策の完了記録と実績の集計を渡す | 施策IDごとの状態・確認根拠、スコア推移、成果指標の出典・集計期間・条件・差分 |
| 調査対象に制約がある | 取得できないページ、未提供の指標、定義の違うデータを明示する | 未採点・未計測・比較不可の理由。集計結果が0の場合は0と表示 |

操作は既存のClaude Codeにまとめ、顧客向けは単独で開けるHTMLにした。顧客は閲覧用のアカウントやダッシュボードへの接続を必要としない。レポートは案件のドメインごとに保存する。施策の実施、広告配信、解析アカウントとの常時接続は手動運用の範囲である。

## 現行版から変更した理由

| 現行版を読み取って確認した点 | 対応 | 優先度 |
|---|---|---|
| 単発の監査、顧客レポート、履歴が別の操作で、採点・施策の転記が必要 | 同じ診断データからHTMLと履歴を生成。採点と施策IDを引き継ぐ | 高 |
| 履歴に成果数値を記録できても、比較した数字の集計条件を示しにくい | 出典、期間、単位、集計定義を指標ごとに記録。比較できる場合に差を表示 | 高 |
| 国内配信が終了した広告媒体や固定の文字数・単価を前提にした手順がある | 検索・地域・国内広告・SNS・メールの判断と出力書式を更新 | 高 |
| 日本語ページの円価格や予約・購入導線を見落とす。取得したHTMLに本文がない場合も採点する | 日本語の抽出、構造化データの扱い、本文欠落時の表示を修正 | 高 |
| READMEで案内していたマーケットプレイスの定義ファイルがない | プラグインとカタログを同梱。展開フォルダを直接指定する起動方法も用意 | 高 |

媒体の変更、確認日と適用日、国内外2製品との比較、次回の再確認項目は[調査記録](marketing-research-2026-11-19.md)に記載した。

## 確認結果

- 工務店とECの合成HTMLを同条件で旧版と比較した。旧版では工務店の構造化データで処理が中断し、ECの税込価格も抽出できなかった。改修版は両ケースに合格した。日本語の予約・購入導線、相対リンク、装飾画像の扱いも照合した。
- 公開ページの取得結果を使い、積水ハウスのタイトルと行動導線を抽出した。ほぼ日ストアは入口HTMLがJavaScript転送のみだったため未採点になり、実際の転送先からタイトルと行動導線を抽出した。この確認は公開HTMLの読み取りが対象である。[住宅サイト](https://www.sekisuihouse.co.jp/)・[ECサイト入口](https://www.1101.com/store/)・[転送先](https://www.1101.com/store.html)
- 架空の工務店のレポートをChromeの幅390pxで表示し、横方向にはみ出さず3施策を読めることを確認した。同じデータのA4 PDFは5ページで、3施策と未計測・0件の表記を照合した。
- 月次HTMLは390pxと1280pxで横にはみ出さず、1列・3列表示と全履歴の展開を確認した。診断・履歴の回帰テストは計8件合格した。
- 履歴は初回、翌月、同日訂正、過去日付、既存形式、並行記録、部分採点、測定条件変更を検証した。保存済みJSONが壊れているケースでは書き換えずにエラーとした。
- Claude Code 2.1.326でマニフェストを検証し、17スキル・6エージェントの登録定義を確認。配布ZIPを展開し、独立した設定でマーケットプレイスを追加してインストールし、2.3.0の有効化を確認した。手動インストールも一時ディレクトリで確認した。Word操作ガイドはLibreOfficeで2ページの日本語表示を確認した。

## 実案件で測る評価指標

以下は次の実地評価の合格目標。競合に対する順位や、実際に達成した数値を示すものではない。

| 指標 | 同じ資料・対象URL・依頼での測り方 | 初回の合格目標 |
|---|---|---|
| 提案までの時間 | 旧版・改修版それぞれで開始から担当者が提出可と判断するまでを計時 | 旧版より中央値を20%以上短縮 |
| 指摘の正確さ | 担当者が上位施策の全指摘を対応するページ・管理資料と照合 | 上位施策の出典確認率100%。事実誤認0件 |
| 修正への着手 | 担当者が追加調査なしで修正担当へ依頼できる施策数を記録 | 上位3件中2件以上 |
| 翌月比較 | 同一施策の実装状況・指標・集計条件まで照合する時間を計時 | 1案件5分以内 |

建設業と別業種を含む複数案件で同じ評価を行い、数字を記録する。この環境でClaude Codeは未ログインのため、認証済みClaudeによる一連の生成時間・提案精度は未測定。顧客の管理画面を使った実績検証と、有料競合製品の同条件操作時間も未測定である。

## 再確認の方法

配布フォルダで次を実行すると、案件データなしでCLIの回帰検証と見本の再生成ができる。

```bash
python3 -B -m unittest discover -s tests -v
claude plugin validate .claude-plugin/plugin.json
claude plugin validate .claude-plugin/marketplace.json --strict
python3 skills/market/scripts/generate_report_html.py examples/construction/report.json /tmp/marketing-example.html
```
