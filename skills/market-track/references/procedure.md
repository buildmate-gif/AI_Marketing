# market-track — 実行手順

## ステップ1：履歴ファイルの確認

対象ドメインのフォルダ（`../market/references/output-location.md` 参照）に `MARKET-HISTORY.json` があるか確認します。

| 状況 | 進め方 |
|---|---|
| ある | 既存の履歴に追記する。ステップ3へ |
| ない | 初回の測定として新規作成する。ステップ2へ |

ドメインごとにフォルダが分かれるため、別URLの履歴と混同する心配はありません。

## ステップ2：初回測定（履歴がない場合）

初回は基準値を作る作業です。ここが雑だと、以降の比較がすべて意味を失います。

1. `/market audit <url>` を実行し、6カテゴリのスコアと総合スコアを取得する
2. 可能なら `/market visual <url>` も実行し、ビジュアルスコアを取得する
3. 実測値を収集する（次のステップ4を参照）
4. `record` コマンドで記録する
5. 「今回が基準値であり、次回以降に比較が可能になる」旨をユーザーに伝える

## ステップ3：2回目以降の測定

**前回と同じ手順で測ってください。** 測定条件を変えると、差分が施策の効果なのか測り方の違いなのか区別できなくなります。

1. 前回の記録を確認する
   ```bash
   python3 "$MARKET_SCRIPTS/track_history.py" report MARKET-HISTORY.json
   ```
2. 前回と同じスキルを同じ順で実行する
3. 実測値を収集する
4. **その期間に実施した施策をユーザーに確認する**（これが最も重要な情報です）
5. `record` コマンドで記録する
6. `report` コマンドで推移を出力し、`TRACK-REPORT.md` にまとめる

## ステップ4：実測値の収集

スコアは推定値ですが、実測値は動かせない事実です。**クライアントへの説得力はこちらの方が圧倒的に高くなります。** 可能な限り収集してください。

| 指標 | 取得方法 | 重要度 |
|---|---|---|
| 月間問い合わせ件数 | クライアントに確認する | 最重要 |
| 月間受注件数 | クライアントに確認する | 最重要 |
| Googleクチコミ件数 | Googleビジネスプロフィールを確認 | 高（建設業） |
| Googleクチコミ評点 | 同上 | 高（建設業） |
| 地図検索順位 | 「地域名＋工種」で地図検索し順位を数える | 高（建設業） |
| 検索順位 | 主要キーワードで検索して順位を確認 | 中 |
| 施工事例の掲載件数 | サイトを数える | 中 |
| 月間サイト訪問数 | クライアントの解析ツールから | 中 |
| SNSフォロワー数 | 各アカウントを確認 | 低 |

**クライアントから数字がもらえない場合**は、自分で取得できるもの（クチコミ件数、地図順位、掲載件数）だけでも記録してください。それだけでも推移は語れます。

`--metrics` にはJSON形式で渡します。

```bash
--metrics '{"月間問い合わせ件数": 27, "Googleクチコミ件数": 45, "地図検索順位": 2}'
```

## ステップ5：記録

```bash
python3 "$MARKET_SCRIPTS/track_history.py" record MARKET-HISTORY.json \
  --url https://example-kensetsu.co.jp \
  --date 2026-07-25 \
  --overall 79 \
  --scores '{"コンテンツ・メッセージング":80,"コンバージョン最適化":76,"SEO・発見可能性":82,"競合ポジショニング":58,"ブランド・信頼性":84,"成長・戦略":68}' \
  --metrics '{"月間問い合わせ件数":27,"Googleクチコミ件数":45,"地図検索順位":2}' \
  --note "地域名＋工種ページを10本追加、施工事例に費用帯を明記"
```

**注意点：**

- `--date` は測定日を `YYYY-MM-DD` で指定します
- 同じ日付で再度記録すると上書きされます（測り直しに対応）
- カテゴリ名は前回と完全に一致させてください。表記が違うと別カテゴリとして扱われます
- `--note` には**実施した施策**を書きます。所見ではありません

## ステップ6：推移レポートの作成

```bash
python3 "$MARKET_SCRIPTS/track_history.py" report MARKET-HISTORY.json
```

出力されたMarkdownをそのまま使えますが、**そこに考察を必ず加えてください。** 表だけでは「で、何が言えるのか」が伝わりません。

考察に含めるべき内容：

1. **最も伸びた項目とその理由** — 実施した施策と対応づける
2. **伸びなかった項目とその原因** — 施策を打っていないのか、打ったが効かなかったのか
3. **実測値との整合** — スコアが上がっているのに問い合わせが増えていない場合、その理由を考察する
4. **次の期間に取り組むべきこと** — 現在の弱点から導く
5. **効果が表れるまでの時間差** — 建設業では、この期間に打った施策の効果が次回以降に出ることを明記する

## ステップ7：スコアが下がった場合の扱い

**隠さず記録し、原因を考察してください。** 下がった原因として考えられるもの：

| 原因 | 確認方法 |
|---|---|
| 競合が施策を打った | `/market competitors` を再実行して比較する |
| 季節要因 | 建設業は年末年始・盆で需要が落ちる。前年同期と比較する |
| 施策が裏目に出た | 変更箇所を特定し、元に戻すことを検討する |
| Googleのアルゴリズム変更 | 同時期に他サイトも順位変動していないか確認する |
| 測定条件のブレ | 前回と同じ手順で測ったか見直す |

**測定条件のブレが疑われる場合は、その旨をレポートに明記してください。** 誤った数字で「悪化した」と報告するのは、報告しないことより有害です。

## 測定の推奨頻度

| 対象 | 頻度 | 理由 |
|---|---|---|
| 建設業（継続支援中） | 1〜3ヶ月ごと | 効果が出るまで3〜6ヶ月かかるため |
| 施策を集中投入した直後 | 1ヶ月後 | 早期の反応を見る |
| 契約更新の提案前 | 必ず1回 | 提案の根拠になる |
| EC・SaaS | 2週間〜1ヶ月 | 変化が速い |

**毎週測るのは避けてください。** 意味のある変化が出ないうえ、ノイズを効果と誤認する原因になります。
