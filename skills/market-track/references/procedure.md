# 測定と保存

## 前回の記録を引き継ぐ

共通の `market/references/output-location.md` に従ってドメインを特定し、案件フォルダを使う。初回は `/market audit` で基準値を取得する。2回目以降は対象ページ、採点基準、主要指標、測定条件を前回と照合する。一部を採点できなかった場合は、レポートの該当スコアを null のまま記録する。

`REPORT-DATA.json` の `priority_actions` がある場合は `id`、`title`、`metric` を引き継ぐ。同じ施策で同じ指標を追う場合は翌月も同じ ID を使用する。同じ案件の別施策に過去の ID を再使用しない。施策の状態は以下から選ぶ。

| 状況 | 記録の根拠 |
|---|---|
| 予定 | 改善案・計画 |
| 進行中 | 作業記録・担当者の報告 |
| 実施済 | 公開ページの変更点、完了報告など、実施を確認した資料 |
| 未確認 | 今回の実施状況を確認できる資料がない |

`evidence` に記録するのは状態を確認できる資料名・該当ページ・確認内容。診断時の指摘箇所しか確認できない場合は「予定」または「未確認」を使う。集計済みの資料を使い、顧客の氏名・メール・連絡先を保存しない。

## 成果指標の測り方

| 業務 | 指標の例 | 確認先と測定条件の例 |
|---|---|---|
| 工務店の集客 | 月間問い合わせ件数 | 台帳の受付日基準、営業・重複を除外 |
| BtoBの資料請求 | 資料請求完了件数 | CRMの受付日基準、対象フォーム名を固定 |
| EC | 注文数 | 受注管理の注文日基準、キャンセル除外 |
| 地域集客 | 評価件数 | 公開プロフィールの同一店舗を同時刻帯で確認 |

利用可能な管理資料から、指標の値を `--metrics`、指標ごとの条件を `--metric-details` に記録する。

- `source` は台帳名や解析画面名、`unit` は「件」「円」などの単位、`basis` は集計定義・対象範囲・除外条件。継続測定では表記を揃える。
- `period` は集計済みの暦月なら `YYYY-MM`、ある日の時点値なら `YYYY-MM-DD`。締まっていない当月を丸1ヶ月として扱わない。任意期間だけの集計は実施メモに期間・値を明記し、月間指標は未計測とする。
- 未取得の値は `null`。0件を確認できた場合だけ `0` とする。従来履歴に出所・期間がなければ「条件未記録」と表示する。
- 前後で同じ取得元・単位・集計条件の数値を異なる暦月同士または異なる時点同士で比較する。指標の定義変更、対象期間の重複、欠測があれば差分を保留する。直近2回の比較が隣接月でないときは実際の期間を明記する。

## 顧客向けレポートから引き継ぐ

新しい診断の `REPORT-DATA.json` がある場合は、対象フォルダ内で次のコマンドを使う。URL、発行日、総合点、カテゴリ点、優先施策を読み取る。スコアが null なら「未採点」と表示する。発行日と診断日が異なる場合は `--date` で診断日を指定する。

```bash
python3 "$MARKET_SCRIPTS/track_history.py" record MARKET-HISTORY.json \
  --from-report REPORT-DATA.json \
  --metrics '{"月間問い合わせ件数":null}'
```

案件の履歴に同じ指標がある場合も、今回の実測は今回の資料から入力する。資料があれば `--metrics` と `--metric-details` を追加する。取り込んだ施策の現状が判明したら、同じ日付でその ID の状況と確認根拠を更新する。

## 手入力で記録・出力する例

以下は架空の11月診断で、締め済みの10月実績を記録する例。実行時は対象案件の資料から作成する。

```bash
python3 "$MARKET_SCRIPTS/track_history.py" record example.jp/MARKET-HISTORY.json \
  --url https://example.jp --date 2026-11-19 --overall 72 \
  --scores '{"コンバージョン最適化":68}' \
  --actions '[{"id":"A01","title":"施工事例に相談ボタンを追加","metric":"月間問い合わせ件数","status":"実施済","evidence":"10月7日の公開記録・施工事例ページ下部で確認"}]' \
  --metrics '{"月間問い合わせ件数":8,"月間受注件数":null}' \
  --metric-details '{"月間問い合わせ件数":{"source":"問い合わせ台帳","period":"2026-10","unit":"件","basis":"受付日基準、営業と重複を除外"}}' \
  --note "施工事例ページに相談ボタンを追加"

python3 "$MARKET_SCRIPTS/track_history.py" diff example.jp/MARKET-HISTORY.json
python3 "$MARKET_SCRIPTS/track_history.py" report example.jp/MARKET-HISTORY.json \
  --html example.jp/TRACK-REPORT.html
```

同一日付を再度記録すると、指定した指標・スコア・施策 ID を更新する。省略した項目の値は保持する。過去日付の追記にも対応する。別ドメインの記録を同じファイルに書こうとするとエラーになる。履歴を同時に更新する際は、スクリプトが隣の隠しロックファイルを使用する。履歴 JSON を他ツールから直接書き換えない。

`--html` は任意。HTMLはオフラインで閲覧でき、スマートフォンでも測定日別の条件を確認できる。

`report` の成功を確認してから出力を案件の `TRACK-REPORT.md` に反映する。初回の `diff` は比較対象がないため省略する。
