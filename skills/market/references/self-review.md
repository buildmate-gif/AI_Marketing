# market — 自己検証ループ

クライアントに渡す成果物は、**出力して終わりにしないでください。** 検証エージェントに検品させ、基準を満たすまで直してから提出します。

## 対象となる成果物

以下は必ず検証を通してください。

| 成果物 | 生成元 | 理由 |
|---|---|---|
| `MARKETING-AUDIT.md` | `/market audit` | 最も網羅的で、提案の土台になる |
| `CLIENT-PROPOSAL.md` | `/market proposal` | 金額と約束が入る。誤りが契約問題に直結する |
| `MARKETING-REPORT.md` | `/market report` | 納品物 |
| PDFレポート | `/market report-pdf` | PDF化する前のJSON段階で検証する |
| `AD-CAMPAIGNS.md` | `/market ads` | 景品表示法のリスクがある |
| `EMAIL-SEQUENCES.md` | `/market emails` | 特定電子メール法のリスクがある |

以下は任意です（社内利用が中心のため）。

`COPY-SUGGESTIONS.md` / `SOCIAL-CALENDAR.md` / `SEO-AUDIT.md` / `LANDING-CRO.md` / `BRAND-VOICE.md` / `FUNNEL-ANALYSIS.md` / `COMPETITOR-REPORT.md` / `VISUAL-AUDIT.md`

## 手順

### 1. 成果物を出力する

通常どおりファイルを生成します。

### 2. market-critic サブエージェントを起動する

```
サブエージェント market-critic に以下を渡す：
  - 検証対象のファイルパス
  - 対象の業種（例：建設・建築業）
  - 対象URL（あれば）
```

market-critic は5観点（具体性・数値根拠・実行可能性・日本語の自然さ・法令リスク）で採点し、書き直し案つきの指摘を返します。

### 3. 判定に応じて対応する

| 判定 | 対応 |
|---|---|
| **合格**（合計35点以上、全観点7点以上） | そのまま提出可。検証を通した旨をユーザーに伝える |
| **条件付き合格**（合計28〜34点） | 指摘された箇所を直してから提出する。再検証は不要 |
| **不合格**（合計27点以下、またはいずれかが6点以下） | 指摘に沿って書き直し、**もう一度検証する** |

**「法令・リスク」が6点以下の場合は、合計点にかかわらず不合格です。** ここは他の観点で補えません。

### 4. 書き直しは2回まで

3回目の検証でも不合格の場合は、ループを止めてユーザーに状況を報告してください。

```
2回書き直しましたが、以下の点が解消できませんでした。
判断をお願いします。

- [残っている問題]
- [その理由：情報が足りない／前提が確認できない など]
```

**同じ内容で無限に書き直さないでください。** 情報が足りないことが原因なら、ユーザーに確認するのが正しい対応です。

## 検証をスキップしてよい場合

- ユーザーが明示的に「検証は不要」と言った場合
- 下書き・たたき台として出力する場合（その旨をユーザーに伝える）
- 社内利用が明らかな成果物

**スキップした場合は、その旨を必ずユーザーに伝えてください。** 黙ってスキップすると、検証済みだと誤解されます。

## よく指摘される問題（先回りして防ぐ）

出力する前に、以下を自分で確認しておくと検証を1回で通せます。

| 観点 | 自己確認 |
|---|---|
| 具体性 | 「改善する」「強化する」で終わっている文がないか |
| 数値根拠 | 試算に前提（訪問数・単価・粗利率・成約率）を書いたか |
| 数値根拠 | 建設業なら「効果発現まで3〜6ヶ月」を書いたか |
| 実行可能性 | 施策の数が多すぎないか。「まず何から」を書いたか |
| 日本語 | ドル記号が残っていないか |
| 日本語 | CVR・CTA・LTV などを初出で説明したか |
| 日本語 | 一人称（弊社／当社）が揺れていないか |
| 法令 | 「No.1」「最安」に根拠を添えたか |
| 法令 | 競合を実名で批判していないか |

## 検証結果の扱い

検証結果そのものはクライアントに渡しません。社内の品質記録として、必要なら `REVIEW-LOG.md` に追記してください。

```markdown
## 2026-07-25 MARKETING-AUDIT.md
判定：条件付き合格（31/50）
指摘：収益試算に粗利率の前提が無かった → 追記して提出
```
