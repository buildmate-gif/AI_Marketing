# ビジュアル診断（見た目の採点）

サイトを実際にブラウザで表示してスクリーンショットを撮り、**画像として見たときの印象**を採点します。HTMLのテキストだけを読む分析では絶対に検出できない問題を見つけるのが目的です。

**出力言語はすべて日本語です。**

## このスキルが必要な理由

従来の `WebFetch` によるHTML取得では、以下が一切分かりません。

- JavaScriptで描画されるサイトは、そもそも中身が取得できない
- 施工写真が「何枚あるか」は分かっても「魅力的に見えるか」は分からない
- 文字と背景のコントラスト、余白、情報の詰まり具合
- スマホで実際にどう折り返され、どこまで見えるか
- CTAボタンが本当に目立っているか

**建設業では施工写真の見せ方が受注を左右します。** テキスト分析だけの診断では、最も重要な要素を評価できません。

## 使う場面

- サイトの見た目・デザインの評価を求められたとき
- 「スマホでどう見えるか」を確認したいとき
- 施工写真・実績写真の見せ方を改善したいとき
- `/market audit` の結果に視覚的な裏づけを加えたいとき
- `/market visual <url>` が実行されたとき

## 進め方

| 段階 | 内容 | 参照ファイル |
|---|---|---|
| 1 | ブラウザでの撮影手順（PC・スマホ・ファーストビュー・全体） | `references/capture.md` |
| 2 | 6項目の視覚採点基準と建設業固有の観点 | `references/scoring.md` |
| 3 | VISUAL-AUDIT.md の書式 | `references/output-format.md` |

## 使用するツール

利用可能なブラウザツールを、次の優先順で使います。

1. **Claude Browser**（`mcp__Claude_Browser__*`）— `preview_start` でURLを開き、`resize_window` で画面サイズを変え、`computer` の `screenshot` で撮影する。最も手軽で確実
2. **Claude in Chrome**（`mcp__claude-in-chrome__*`）— ログインが必要なページを見る場合
3. **どちらも使えない場合** — その旨をユーザーに伝え、手動でスクリーンショットを撮って渡してもらうか、テキストベースの `/market landing` で代替することを提案する

**ブラウザツールが無いまま推測で見た目を評価しないでください。** 見ていないものを採点するのは、このスキルの目的に反します。

## 撮影する画面

| 画面 | サイズ | 目的 |
|---|---|---|
| PC・ファーストビュー | 1280×800 | 第一印象の評価 |
| PC・ページ全体 | 1280×幅いっぱい | 情報設計と流れの評価 |
| スマホ・ファーストビュー | 375×812 | 実際の主要閲覧環境 |
| スマホ・ページ全体 | 375×幅いっぱい | 折り返しと縦の長さ |
| 施工事例ページ | PC・スマホ両方 | 写真の見せ方（建設業では必須） |
| 問い合わせフォーム | スマホ | 入力のしやすさ |

## 出力

- `<ドメイン>/VISUAL-AUDIT.md`（規則は `../market/references/output-location.md`）
- 総合ビジュアルスコア（0〜100）

## 他スキルとの連携

- `/market audit` の「コンバージョン最適化」「ブランド・信頼性」の採点根拠として使う
- `/market landing` と併用すると、テキストと見た目の両面からLPを評価できる
- `MARKETING-AUDIT.md` があれば、そのスコアと視覚評価の食い違いを指摘する（テキストは良いが見た目が古い、など）
